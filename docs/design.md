# UI 汉化维护与双仓拆分方案

日期：2026-10-13。状态：实现与本地验证完成，公开翻译包已发布；游戏与真实模型验收待执行。交付证据见 [验证记录](verification.md)。

## 目标与边界

将 TSKHook-Plus 中已增加的 UI 汉化能力整理为可独立审阅、适合向 TSKModding/TSKHook 提交的功能；翻译生产工具、工作文件和翻译数据迁至 `Azure-Sora/TSKHook-UITranslations`。

保留上游变速、截图、剧情翻译、窗口尺寸、FPS 与立绘缩放行为。用户明确允许统一改造配置层：所有配置接入 BepInEx 配置管理，F1 改为打开/关闭 ConfigurationManager，配置页提供原 F1 的重载能力。其余上游业务代码不借机重写。

放弃 Sprite/Spine 图片提取与替换方向，不合入实验分支，不制作图片翻译工具。既有 Git 历史保留用于追溯，不在本次工作中重写历史。

## 两仓归属

| 内容 | TSKHook-Plus | TSKHook-UITranslations |
| --- | --- | --- |
| 游戏钩子、字体兼容、运行时翻译 | 维护 | 不复制游戏集成 |
| 全部插件设置、ConfigurationManager 接入 | 维护 | 不实现游戏内设置窗口 |
| 增量文本捕获、翻译包更新和回退 | 维护 | 消费捕获、生产翻译包 |
| 数据格式、身份键、必要校验规则 | 维护可复用的纯托管协议库 | 引用固定版本协议库 |
| 独立 Windows 翻译工作台 | 不包含 | 维护 |
| 分类归档、模型调用、审校与编译工具 | 迁出 | 维护 |
| 原文、译文、术语表、翻译指导 | 迁出 | 维护 |
| 翻译包发布工作流 | 迁出 | 维护 |

两仓通过明确版本的数据协议衔接。插件构建不依赖个人翻译仓库，不把翻译数据或工作台带入上游 PR。工作台不复制游戏程序集。共享的纯托管代码只保留一个权威来源，以固定 Git revision 或包版本引用，不建立浮动的相邻目录隐式依赖。

## 配置设计

使用 BepInEx `Config.Bind`、描述、合法范围和枚举定义统一配置；接入 `anosu/BepInEx.ConfigurationManager` 的 BepInEx 6 / IL2CPP 发行版。ConfigurationManager 负责窗口和 F1，不在插件中再处理同一按键，避免双重触发。

旧 `BepInEx/plugins/config.json` 仅在首次迁移时读取，旧文件保留。新配置成功保存后才记录迁移完成；已有新配置不被旧文件覆盖。热键和窗口中的更改写入同一配置项。非法旧值安全回落并记录具体字段。

支持即时应用的设置在 Unity 主线程下一帧生效。配置变化不得在后台回调直接调用 Unity。重载操作从磁盘读取配置、应用窗口设置、重载 UI 译文和确保字体可用；禁止把刷新管理器列表当作配置重载。IL2CPP 分支不支持外部 GUILayout CustomDrawer，先以标准操作枚举实现重载/检查更新等一次性操作并自动恢复为空闲，实际控件以兼容性验证结果为准。

设置分组：常规、翻译、捕获、更新、维护。普通玩家无需配置模型密钥。捕获默认关闭，可在游戏中反复开关，退出时可靠刷盘。

## 捕获与工作台

插件捕获结构化文本，过滤账号字段、去重、缓冲落盘。工作台监听捕获目录并定期补扫，支持未开启工作台时积累的记录。记录不完整的最后一行等待后续写完，不将一次监听通知当作完整事务。

工作台提供：

1. 选择游戏、捕获和翻译工作目录；记住本地设置。
2. 增量归档、稳定身份合并、分类和冲突报告；保留旧记录及人工译文。
3. 仅为新增或原文变化的条目创建翻译任务；相同身份的原文变化标记 stale。
4. 可配置模型端点、模型名、并发和批次；调用前注入术语及上下文，支持取消、重试与续跑。
5. 源文/译文对照、搜索筛选、人工编辑和问题列表；reviewed/verified 不被自动重译覆盖。
6. 标签、占位符、数值、换行等程序校验。机器输出仅标记 translated，不能声称人工或实机验证。
7. 本地编译、安装预览和发布准备；公共发布由维护者明确触发。

本地密钥、任务缓存、日志、原始捕获和模型返回不入 Git。凭据仅保存在本机，界面不回显或打印。工作台使用普通 Windows 桌面窗口，避免要求维护者运行多个命令行工具。

## 翻译包与热更新

清单包含协议版本、翻译包版本、最低插件版本、下载地址、字节大小、SHA-256、条目数。发布包是 JSONL 数据，不执行远程代码。源工作文件与生成产物区分，编译失败不得发布。

插件后台下载到临时文件，校验清单兼容性、大小、哈希和完整 JSONL 后原子切换。下载或解析失败继续使用旧包，保留上一份可用包并支持回退。版本状态只有在文件和索引切换成功后更新。本地预览与公共更新有明确模式，避免后台更新覆盖正在测试的译文。

热更新表示新索引生效；已由游戏缓存或已渲染的文字可能需要重新打开页面。不得承诺所有现有页面原地刷新。

网络响应中的控制字段必须保持原文。既有 source-hash 回退不能绕过受保护字段；新翻译自动化不能扩大未知字段的替换范围。图片文字和未实际加载的技能属于既有覆盖边界。

## 迁移方式

起点为 TSKHook-Plus `9c3ecdf4073f7eebf79088023c7042f338e46d6d`。先清点受 Git 管理的翻译文件、工具和许可证，复制到新仓并保存来源记录、逐文件哈希；验证编译得到等价译文后再从插件仓删除对应内容并修正构建、测试、发布和文档引用。不删除本地原始捕获、不重写旧提交。

新仓公开托管已有公开翻译资料，工作台源代码同时维护。插件仓与新仓分别构建、验证和提交；新仓创建和初始发布属于用户本次已授权拆仓工作。上游 PR 在功能和证据整理到可审阅状态后单独推进，不将未验证的游戏行为表述为通过。

## 实施阶段与验收

1. **设计与基线**：本文、文件归属、环境与历史基线记录。
2. **拆仓与纯托管核心**：新仓创建，数据校验，工具迁移，旧路径引用清理；现有编译与冒烟测试继续通过。
3. **配置与生命周期**：旧配置迁移、标准设置、F1 管理器、重载操作、动态捕获；配置测试与插件编译。
4. **翻译工作台**：可启动程序、自动导入、翻译队列、审校、编译预览与发布准备；离线端到端及模型协议错误测试。
5. **更新与交付**：有效更新、损坏包拒绝、断网保留、回退测试；两仓独立构建与使用文档。
6. **实机验收**：游戏中 F1、中文字体、输入、设置应用、捕获开关、翻译包应用与页面刷新。未执行的项目明确 NOT_RUN；本地替身测试不作为实机证据。
