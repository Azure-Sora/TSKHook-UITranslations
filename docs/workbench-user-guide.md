# 翻译工作台使用说明

## 首次运行

1. 将翻译仓库克隆到本机：`git clone --recurse-submodules https://github.com/Azure-Sora/TSKHook-UITranslations.git`。
2. 解压 Windows 工作台，运行 `TSKHook-UITranslations.exe`。自包含发行包无需另装 .NET。
3. 在“模型与路径”选择刚克隆的仓库根目录和游戏根目录。捕获目录通常为 `游戏/BepInEx/plugins/TSKHook/ui_capture`。
4. 填写兼容 Chat Completions 的完整模型地址、模型名、API Key、每批数量、并发数和输出 token 上限，然后“保存设置并加载”。接口地址可使用 HTTPS；本机模型允许 loopback HTTP。

模型 API Key 与 GitHub Token 使用 Windows DPAPI 加密，存在当前账户的 `%LOCALAPPDATA%/TSKHook-UITranslations/credentials.bin`；路径及非秘密配置存在旁边的 `settings.json`。不要共享这个目录。GitHub Token 只用于发布，不需要提供给玩家。

## 日常流程

在游戏按 F1 打开配置管理器，开启捕获。工作台默认每五秒检查捕获目录，自动去重、按稳定身份归档并保留人工译文。工作台不启动时插件仍会捕获，下次打开会补处理。尚未写完的最后一行会等待后续数据。

“翻译待办”仅处理 new/stale，已审校、已验证、冲突、排除和待核对条目不会被模型覆盖。勾选“自动翻译”后，新条目会自动发送给配置的接口并产生用量。成功结果逐批保存，中途暂停后再次运行即可续跑。失败条目保留在本地重试列表，不会每五秒反复请求；修改接口设置后可使用“重试失败任务”。原始 token 用量记录在 `.local/model-usage.jsonl`，供应商未返回的字段为 null，不估算成零。

机器译文状态为 translated；标签、占位符、数值或换行异常会进入 needs_review。工作队列支持全文搜索和筛选；一次显示前 1,000 条以保持流畅，搜索仍覆盖全库。选择条目后可编辑译文，保存并标记已审校；只有自己进游戏确认后才使用“实机确认”。“保留原文 / 排除”使该条不进入运行包。

不要同时用两个程序编辑同一个工作目录。若外部工具修改了分类文件，工作台会要求重新加载，防止覆盖外部修改。归档的多文件事务可在下次加载时恢复。

## 重复原文与技能正式文本（0.2）

“合并重复原文”默认开启：同分类、同字段、完全相同原文且审校状态/现有译文相同的记录合为一组，“位置”列显示关联数量。原来的 key、ID 和运行时匹配关系仍全部保留。搜索可匹配组内任一 key。取消合并可按单个位置修订；已有不同译文的原文会提示分歧，不自动互相覆盖。

“保存并标记已审校”和“保留原文 / 排除”作用于当前组全部位置。“实机确认”需要取消合并后按实际验证的位置记录。组内记录在编辑期间变化时会拒绝保存，避免覆盖新结果。

“翻译待办”按组请求模型，一份结果回填本组仍未修改的位置；人工修改优先。每批条数现在指唯一翻译任务数。“复用已有译文”可把结构校验通过且无分歧的同源译文应用到待办，不调用模型；开始模型翻译时也会先执行复用。复用结果为机器初译，不冒充人工审校或实机验证。搜索只影响显示，仍不限制“翻译待办”的范围。

“预览与发布”新增“生成技能正式文本”；编译、安装预览和发布前也自动执行。它把已翻译的升级预览原文及译文中的 `<color>` 标签移除，生成带正确源文哈希的正式文本，并同步尚未人工审校的生成译文。重复执行不会增加重复条目；预览译文存在分歧时不猜选结果，已捕获的正式文本和人工审校结果保留。它不推算未知等级的数值，也不能补齐从未捕获的技能。

## 本地预览

### 编号名称模板（0.3）

勾选“合并重复 / 编号模板”时，同分类、stage_name 字段中形如 `水神の塔1F` 的名称，至少出现 3 个不同楼层后，归为 `水神の塔{floor}F` 一个任务。界面显示覆盖的位置数，悬停原文查看具体来源；搜索 `水神の塔230F` 也能找到所属组。

手动填写 `水神之塔{floor}F` 并保存即可填回各条原楼层；也可让模型翻译这个模板，一次请求结果应用到全组。占位符必须完整保留一次，不得填固定楼层号；丢失占位符的模型结果不会写回。底层每条 key、sourceHash、编号均保留，运行包中没有模板占位符。排除整组时分别保留每条实际原文。

“复用已有译文”也识别楼层：至少两个不同楼层已有结构合格且归一后完全一致的译文时，可直接填充同系列其他待办；不同模板、人工译文分歧均不强行覆盖。

当前仅启用上述塔层名称规则，不替换任意数字，不对技能伤害、日期、金额、多数字句子做类推。不同塔名、字段、审校状态分组保留；取消合并可以逐位置编辑或实机确认。

“编译并检查”产生 `.local/packages/<版本>/` 中的 JSONL、manifest 和完整校验报告。编译器使用主文件的 key/sourceHash，分类文件负责 translation/status；标签和占位符错误会阻止编译。new/stale/conflict/needs_review/excluded 不发布。

“安装到本机预览”将包原子写入游戏 `BepInEx/plugins/TSKHook/ui_preview.jsonl`。在游戏 F1 设置中开启“本地预览模式”后，插件每两秒检查文件变化，期间暂停公共翻译更新。已经打开的界面可能需要重新进入。此按钮不替换 DLL，也不修改正式远程包。

## 发布

发布前确认在翻译仓 `main` 分支，Git 凭据已配置，暂存区没有其他更改。在设置页填写对该仓具有 Contents 写权限的 GitHub Token。

填写未使用过的版本号，例如 `2026.10.13.1`。点击发布会先编译并展示待确认的条目数和警告数；确认后提交并推送 `translations/ui` 的更改，再创建 GitHub 草稿 Release，上传完整资产，最后公开该 Release。失败的上传保留为草稿，不对玩家开放；请检查草稿后使用新版本号重试。不会覆盖已有 Release。

翻译发布标签为 `translations-<版本>`，玩家默认读取最新正式 Release 的 `manifest.json`。工作台程序使用 `workbench-v*` 标签发布预览版，明确不占用正式翻译的 latest 通道。

## 既有数据的核对提示

迁移基线共有 46,042 条源记录、45,414 条运行译文、628 条未翻译条目。编译结果保留了原有的 894 个数字差异和 410 个换行差异提示，不表示全部都是错译。另外发现 17 条历史原文显示乱码、与保存的 sourceHash 不一致；不会擅自重算这些哈希，也不会将这些原文自动送给模型，重新捕获到同一原文哈希后可修复显示文本。

这套工具只处理实际捕获到的文本。按需加载的未拥有角色/技能以及图片文字仍是覆盖边界。

## 命令行与开发

开发需要 .NET 10 SDK；共享协议库固定引用 `vendor/TSKHook` 的 Git revision。

```powershell
dotnet run --project app/Workbench
dotnet run --project tools/CompileUiTranslations -- path/to/ui_texts_v2.jsonl .
dotnet run --project tools/CompileUiRuntime -- . .local/compiled/ui_translations.jsonl
dotnet run --project tools/BuildPackage -- 2026.10.13.1 . Azure-Sora/TSKHook-UITranslations
dotnet run --project tests/WorkbenchTests -c Release -- .
./scripts/Build-Workbench.ps1
```

`tools/BuildPackage` 的 `--publish` 开关用于显式命令行发布，凭据从进程环境变量 `TSKHOOK_GITHUB_TOKEN` 读取。普通使用建议直接操作工作台。

0.3.1 起，模型无法可靠翻译时可以返回空译文，工作台将该项标记为“需要核对”，同批其余有效结果继续保存。不会因为单项留空反复重试整批。输出仍必须完整包含每个输入的 key/sourceHash/translation，不得添加 status 或省略项目。


## 查看翻译进展（0.3.2）

点击“翻译待办”后，顶部状态区立即显示准备中，再显示本轮任务总数、已处理任务、批次、进行中批次、已保存位置、失败任务和耗时。整理队列在后台执行；运行时禁止重复启动，可以点击“暂停翻译”。状态区切换页面后仍可见。

模型按批返回，等待期间任务进度不增长，但耗时持续更新。临时错误和格式错误重试时会显示批次、等待秒数与尝试次数。进度条统计已处理任务（包括失败），不是已验收译文；保存位置包含待核对结果。底部保留详细日志及模型用量。

结束后状态区保留完成、部分失败、暂停或配置错误的摘要。没有可发送条目时明确提示；此前失败的任务需点击“重试失败任务”，分歧文本需人工核对。暂停保留已保存结果。


## 完成剩余条目的收尾（0.4.0）

工作队列现在按“可自动翻译 / 译文待统一 / 译文待修正 / 捕获冲突”分类。顶部待翻译数字不再把因译文分歧而跳过的项目算成可自动翻译。原始状态仍显示在单独一列。

建议依次处理：

1. 点击“重新校验”。只将非空且新版校验已无问题的待核对结果恢复成机器初译，保留原文、原哈希和译文，不调用模型、不冒充人工审校。全角数字与等值半角数字不再误报；`50%HP`、`20%ATK` 不再被当成占位符，真实格式占位符和数字变化仍检查。
2. 在“译文待统一”选中一条，打开右侧“已有译文”。每个候选显示位置数和审校状态，悬停可看具体位置。“采用到编辑框”只填入文本，检查后点“保存审校”只保存当前组。“统一同原文译文…”会确认覆盖范围，再统一同分类、字段、原文及哈希的所有未排除、非冲突位置。包含已人工审校位置时会说明数量，统一后均为已审校，原实机确认不沿用。楼层模板不提供跨层统一按钮。
3. 在“译文待修正”查看右侧提示及“问题与冲突”详情。可修订后保存，也可“重译当前组”：只发送当前组，不受其他位置译文分歧限制，不会修改其他待办或人工审校结果；会产生模型用量。已审校、已实机确认、已排除、受保护字段、失效原文和捕获冲突不能直接重译。模型仍不确定而留空时继续保留待核对。
4. 对数字/换行等非致命告警，确认差异合理后保存审校，即从收尾队列移出；它们仍留在详情和编译诊断中。标签或真实占位符缺失不能直接审校通过。
5. 在“捕获冲突”的“问题与冲突”页，对照所有相关原文、草稿、匹配位置、来源及首次捕获时间。可复制详情用于修复捕获/匹配规则。若本轮暂不处理，点“暂不发布该冲突组…”，确认后整组排除，但保留全部原文、草稿和来源；在“已排除”可查阅。此动作不会修复插件匹配规则，也不会将某一个原文强行选为正确版本。

普通审校和译文统一均检查数据是否在操作期间发生变化，避免覆盖后台新结果。“实机确认”仍只记录实际在游戏中验证过的单个位置。

“收尾总览”也会纳入既有机器译文的分歧和校验告警，因此数量可能高于旧版仅按状态显示的“待处理”列表；不代表新增了错误。已人工确认的非致命差异不重复列为待办。

## 敌人身份修复（0.4.1）

插件 1.4.2 与工作台共享新规则：缺少 unit_id 的 enemy_data 名称/说明使用原文完整 SHA-256 区分，同一关卡不同敌人不再被合并为捕获冲突。有 unit_id 的角色匹配不变。

在“问题与冲突”点击“修复敌人身份”。操作先自动备份主文件、分类文件、冲突文件及已有失败记录到 `.local/backups/enemy-identity-*`，包含校验清单和旧新 key 映射，再原子保存迁移结果。仅迁移全部来源都能证明是旧 enemy_data 身份的记录；原文哈希错误、混合来源或已有新记录与旧记录译文不同的项目保留待核对。原文与哈希不变，人工审校与主动排除状态保留。空白名称仅复用已完成且校验通过、完全一致的同原文名称译文，不调用模型。没有可靠译文的冲突解除后回到待翻译。

重复执行不会重复迁移。开始前请暂停模型翻译并保存编辑。发布迁移后的译文时配套更新游戏目录中的 TSKHook.dll 与 TSKHook.Translation.Core.dll；未覆盖的其他冲突仍需分别处理。

## 模型统一、核对与多模型供应商（0.5.0）

### 同一供应商保存多个模型

在“模型与路径”选择或新增供应商，保存名称、完整 chat/completions 地址、API Key，以及每行一个的模型名称。一个 API Key 可用于该供应商下的多个模型；不同供应商分别保存凭据，仍由当前 Windows 账户加密。

页面顶部单独选择“初翻模型”和“核对模型”，例如初翻用 Gemini、核对用 Claude。同名模型也会按所属供应商分别显示和调用。“翻译待办 / 重试失败任务 / 重译当前组 / 自动翻译”使用初翻选择；模型统一与核对使用核对选择。批量、并发和输出上限为两类任务共用。点击“保存设置并加载”保存配置。旧版的单接口与模型配置会保留并迁移为现有供应商；删除某个已选模型后需重新选择，不会悄悄切到别的模型。

### 让模型处理待统一项

“模型批量统一”处理整个工作目录中可处理的同原文译文分歧；搜索与列表的前1000条显示限制不缩小批量范围。在“已有译文”可以点击“模型选择并统一”，只处理当前原文对应的全部非人工位置。

核对模型收到原文、已有候选、人工确认标记、结构告警和来源上下文，只能选用某一个已有候选，不能混合或另写一个版本。结果自动保存为机器译文，并附带“模型已核对”标记、所用模型、时间和判断理由。人工审校、实机确认、主动排除及捕获冲突不被覆盖；若候选不足以判断、语境不一致或人工确认内容相互冲突，则保留待处理。

### 让模型判断是否确需修正

“模型批量核对”处理整个工作目录的待修正内容；“编辑译文”中的“模型核对当前组”只处理选中组。核对模型可选择：

- 保留：当前译文正确，原有告警是可解释的差异。
- 修正：确有错译、漏译或机制错误，返回完整修正版并自动保存。
- 暂缓：证据不足，保留原译文和待处理状态，记录原因。

空译文不能被判为通过，真实标签或占位符损坏不能被忽略。数值或换行差异只有在模型明确确认并解释后才可关闭待办，原始校验提示仍保留。在“问题与冲突”查看具体理由；“模型已核对”筛选与“已人工审校”分开。原文或译文变化后，旧判断失效；新增不同候选会重新进入待统一。

这些动作会调用所选核对模型并产生用量。顶部显示任务数、批次、等待、已保存位置和失败数，可随时“暂停任务”。已保存结果保留，未完成任务留在队列；再次点击对应批量按钮可继续。自动翻译不会自动启动核对任务。模型响应期间发生人工修改或出现新的同原文位置时，过期结果会被跳过。

每批核对将原状态、原译文、模型结果及理由保存在 `.local/model-reviews/`，与译文写入同一事务；用量写入 `.local/model-usage.jsonl`，核对失败清单为 `.local/model-review-failures.json`。不在这些记录里保存 API Key 或供应商错误响应正文。

### 其余捕获冲突

“修复捕获身份”现覆盖敌人名称、编号角色的名称变体、活动页签、复用关卡名称及姐妹技能说明的彩色/纯文本或效果变体。所有原文分别匹配，同原文重复记录仅在译文和排除状态兼容时合并。操作有完整备份、哈希清单与旧新 key 映射；无法证明的记录仍保留待核对。

0.5.0 编译的公开译文包要求插件至少为 1.4.3。请先为玩家提供配套插件，再发布新版译文；本地预览不改动公共活动包。

## 0.5.1：慢模型等待与失败提示

模型请求现在最多等待 15 分钟，包含响应头及完整响应正文；初翻与核对共用这一策略。超时、连接中断和 HTTP 5xx 不自动重发，因为供应商可能仍在处理并计费。只有明确的 HTTP 429 限流、或已收到但格式不合规的结果会按原有上限重试（格式重试仍会产生额外用量）。用户暂停立即取消本地等待，但不能保证取消供应商后台任务。

日志区分超时、连接中断、限流和 HTTP 状态码，不保存敏感响应正文。核对存在失败时标题显示“结束 · 有失败任务”。旧版的 TransientModelException 无法事后区分具体原因。

若遇到旧版约 9 分钟后整批失败、供应商却有多条调用记录，请关闭旧版，打开 0.5.1。先选一组待统一内容，使用“模型选择并统一”确认接口响应可正常保存，再运行批量统一。此前失败的译文仍在原队列；重新运行会再次产生请求，建议先确认供应商旧请求已经结束。

## 0.5.2：核对协议、逐项保存与用量控制

0.5.1 只解决了等待超时，仍存在提示词混入初翻输出协议、要求重抄长文本、整批校验失败后重复调用的问题。0.5.2 对核对使用独立协议，保留术语和名称参考，不再拼入初翻的三字段输出规范。

- 统一候选：模型只返回本批整数 id、动作、候选编号、简短理由和告警确认。工作台从原始快照取候选全文；模型不重抄译文、key 或 sourceHash。
- 核对修正：accept 由程序保留原译文；只有 revise 需要返回新译文。defer 保留待办。每个候选均提供自身的结构/数值/换行告警。
- 一条校验不通过只影响该条，同批合法结果正常保存。乱序按 id 对应，漏项、重复 id、错误字段均单独说明；完整 JSON 无法解析时保留整批待办。人工确认、原文哈希、内容变化和致命结构校验仍然生效。
- 核对请求不再自动重发，包括非法输出、限流与网络错误。再次点击仍会调用模型，请先阅读失败原因。初翻重试规则不受本次核对修改影响。
- 核对每批最多 8 项，并按请求内容长度进一步拆分；单项过长则本地报错，不发送。请求使用直接 Unicode，不再把中日文变为大量字面 Unicode 转义。模型、供应商和用户设置仍保留。

已收到的核对文本、结束原因、用量和本批 id 映射保存在 `.local/model-review-responses/`；同名 `.validation.json` 记录逐条拒绝原因。记录不包含 API Key、请求头或供应商错误响应正文。它们是排障材料，不会自动恢复或覆盖译文；可用于之后的离线检查，避免重复付费。日志同时给出 numbers、newlines、tags、缺失 id 等具体原因。旧版未保存的失败响应无法追溯恢复。
